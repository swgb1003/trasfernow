# TRANSFER NOW（仮）
## サッカー移籍情報特化型スマートフォンアプリ 開発仕様書

**Version:** 1.0
**対象:** iOS / Android
**開発方式:** Flutterによるクロスプラットフォーム開発

---

# 1. アプリ概要

## 1.1 コンセプト

**「世界の移籍市場を、リアルタイムで追いかける。」**

TRANSFER NOWは、世界中のサッカー選手の**移籍情報・移籍の噂・交渉状況・正式発表**を一つのアプリに集約する、移籍市場特化型スマートフォンアプリである。

一般的なサッカーニュースアプリでは、

- 「クラブが選手に興味」
- 「代理人と接触」
- 「正式オファー」
- 「個人合意」
- 「移籍間近」
- 「正式加入」

といった情報が、それぞれ別の記事として掲載される。

TRANSFER NOWではこれらを**「1つの移籍案件」**として管理する。

ユーザーはニュース記事を一つずつ探すのではなく、

> 「この移籍、今どうなってる？」

を数秒で確認できる。

---

# 2. 解決する課題

現在の移籍情報には以下の問題がある。

### 情報が分散している

移籍情報はニュースサイト、SNS、現地メディア、記者など複数の情報源に分散している。

### 同じ移籍について大量の記事が出る

例えば1人の選手について、

「Chelseaが関心」

「Chelseaが代理人と接触」

「Chelseaが正式オファー」

と別々の記事が公開されるため、現在どの段階なのか分かりにくい。

### 海外情報を追うのが大変

有力な情報が英語・スペイン語・イタリア語などで発信される場合、日本のユーザーがリアルタイムで追跡するには負担が大きい。

### 「噂」と「確定情報」の区別が難しい

SNSでは信頼性の低い情報も拡散されるため、移籍の実現可能性を判断しにくい。

# 4. アプリ最大の特徴

TRANSFER NOWは単なるニュースアプリではない。

中心となる考え方は、

## 「ニュース」ではなく「移籍案件」を追跡する

ことである。

例：

### PLAYER A → CHELSEA

**移籍成立可能性：82%**

8月12日
🔵 Chelseaが選手に関心

↓

8月14日
📞 代理人との接触を開始

↓

8月16日
💰 €50mの正式オファー

↓

8月17日
🤝 選手側と個人条件で基本合意

↓

8月19日
🔥 クラブ間交渉が最終段階

↓

8月20日
✅ OFFICIAL

このように、一連の移籍報道を一本のストーリーとして確認できる。

# 8. 移籍ステータス

各移籍案件にはステータスを設定する。

### RUMOUR

🔵 噂

初期報道。

### INTEREST

👀 関心

クラブが選手を獲得候補として検討。

### CONTACT

📞 接触

クラブが代理人・選手側へ接触。

### NEGOTIATION

💬 交渉

移籍条件について具体的な交渉。

### BID

💰 オファー

正式な移籍金提示。

### AGREEMENT

🤝 合意間近

個人条件またはクラブ間条件で合意。

### FINAL STAGE

🔥 最終段階

移籍成立が非常に近い状態。

### OFFICIAL

✅ 正式発表

クラブ公式発表済み。

### COLLAPSED

❌ 破談

交渉終了。

# 9. 移籍成立可能性メーター

0〜100%で移籍成立可能性を表示する。

例：

**18%**

「噂レベル」

**46%**

「交渉の可能性あり」

**72%**

「移籍の可能性が高まっています」

**91%**

「成立間近」

**100%**

「OFFICIAL」

ただし、この数値については「客観的事実」ではなく、情報源や交渉状況などを基にした**推定値であることを明記する。**

# 10. AI移籍記者

生成AIを利用した対話機能。

ユーザーは自然言語で移籍情報について質問できる。

例：

**ユーザー**

「今日Chelseaで何か動いた？」

**AI**

「本日は3件の移籍案件に動きがあります。

最も進展しているのはPLAYER Aの獲得交渉です。

複数の情報源がクラブ間交渉の進展を報じており、現在の推定成立可能性は82%です。」

その他、

「今日一番デカい移籍ニュースは？」

「Arsenalが狙っているFW教えて」

「Liverpoolから退団しそうな選手いる？」

「この移籍って本当にありそう？」

などの質問に対応する。

# 11. AIニュース要約

# 36. 開発方針

最初の開発目標は、

**「プレミアリーグ移籍情報だけで完全に動くMVP」**

とする。

まず、

**Flutter UI → ダミーデータ → TransferCase → Supabase → Football API → AI → Push通知**

の順番で実装する。

最初からAPI連携を行うのではなく、ダミーの移籍案件を10〜20件作成して全画面を完成させる。

UIと画面遷移が完成した段階でバックエンド・外部APIへ接続する。

これによってAPI側の問題とFlutter側の問題を切り分けやすくし、個人開発でも段階的に完成させられる構成とする。
